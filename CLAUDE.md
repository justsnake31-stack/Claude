# Контроль сроков

Веб-приложение для iPhone (PWA) для кухни пиццерии: повар фотографирует термо-этикетки на контейнерах,
приложение само читает название и сроки и показывает, что списать сегодня и что уже просрочено.
Пользователь общается по-русски и не программист — отвечай по-русски, простыми словами, без жаргона.

- Сайт: https://justsnake31-stack.github.io/Claude/ (GitHub Pages, ветка `master`, корень репозитория).
- Всё работает на телефоне, без сервера и без платных API. Распознавание — на устройстве.

## Устройство

- `index.html` — всё приложение: разметка, стили и весь JavaScript в одном `<script>`. Ключевые места:
  - `getPaddle` / `recognizePaddle` / `paddleLines` — основной движок OCR (PaddleOCR PP-OCRv5, модель `eslav` для русского), пробует повороты 0/180/90/270;
  - `recognizeFile` + `findLabels*`, `prepCrop` — старый путь через Tesseract, только запасной;
  - `parseLabel`, `findDates`, `fixDM`, `toDate` — разбор текста этикетки в название и сроки (самое важное и самое хрупкое);
  - `PRODUCTS` + `matchProduct`, `BRANDS` + `stripBrand` — каталог продуктов из выгрузки остатков и поставщики;
  - `APP_VERSION` — версия в шапке; `pump` — очередь фото; `listText` — окно «Список на списание».
- `sw.js` — сервис-воркер: `CACHE` (приложение, network-first) и `ENGINE` (файлы `ocr/`, cache-first, ~38 МБ).
- `ocr/` — самостоятельно размещённый движок (сборка `@paddleocr/paddleocr-js`, onnxruntime-web wasm, модели); как пересобрать — `ocr/README.md`. Не редактировать руками.
- `lab/` — старая страница сравнения алгоритмов, в приложении не используется.
- `tests/` — эталонные фото этикеток, правильные ответы и прогон (`node tests/run.cjs`).

## Правила этикеток (не нарушать)

Этикетка: название, поставщик в кавычках, температура хранения в скобках, затем даты `ДД.ММ.ГГ, ЧЧ:ММ`:
- 2 даты: изготовлено/вскрыто → годен до;
- 3 даты: достали → разморозится → годен до.

Срок годности — всегда ПОСЛЕДНЯЯ дата. Даты идут по возрастанию. Если дата не прочиталась, перепутан порядок, дата далеко от сегодня
или у срока нет времени — не угадывать, а отправлять на ручную проверку («Впишите вручную»). Ложный срок, показанный как настоящий,
хуже, чем «не прочитано». При изменениях этой логики — субагент `label-safety-reviewer`.

## Как работать

- После любого изменения распознавания — навык `ocr-regression` (`node tests/run.cjs`), сообщать «было → стало» по срокам/названиям.
  Эталон в `tests/baseline.json` не должен ухудшаться, строк `!!!` быть не должно.
- Выпуск — навык `/release`: поднять `APP_VERSION` (index.html) и `CACHE` (sw.js; при изменении `ocr/` — ещё `ENGINE`), прогнать тесты, коммит, push.
  Хук перед `git push` не даст отправить изменённое приложение без поднятой версии.
- Хук после правок проверяет синтаксис JavaScript в index.html — если он сообщил об ошибке, исправь сразу.
- Проверить вид на телефоне: Playwright (`require('playwright')`, устройство `iPhone 13`) против локального сервера; сеть к github.io из облачной среды закрыта.
- Новые фото от пользователя — добавлять в `tests/photos` + `tests/truth.json` (правильный ответ — глазами с фото).
- Коммиты на английском; пользователю — по-русски.
