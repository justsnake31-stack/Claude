# Регрессионный прогон распознавания

Проверяет, что изменения не ухудшили чтение сроков и названий на реальных фото этикеток с кухни.

## Запуск

```bash
node tests/run.cjs                 # все фото (~2 минуты)
node tests/run.cjs r04.jpg s4.jpg  # только выбранные — для быстрой отладки
VERBOSE=1 node tests/run.cjs       # плюс сырой текст OCR и подпись для промахов
```

Скрипт поднимает локальный сервер, открывает `index.html` в Chromium с экраном iPhone, «загружает» фото через кнопку «Из галереи» и читает результаты из localStorage. Дата в браузере зафиксирована на день съёмки (`tests/baseline.json` → `today`), иначе сроки «уехали» бы.

## Как читать результат

Каждая строка: `статус N/n файл срок название | ждём …`
- `OK` — срок верный;
- `man` — ушло в «Впишите вручную» (безопасно, но это промах);
- `!!!` — **неверный срок показан как настоящий**. Это самое опасное: продукт попадёт не в тот список. Любой `!!!` — провал, даже если общий счёт вырос;
- `N`/`n` — название совпало с ожидаемым / нет.

Итоговая строка сравнивает со счётом из `tests/baseline.json`. Код выхода 1 = стало хуже эталона или появился ложный срок.

## Правила

1. Сообщай пользователю итог в виде «было X/20 → стало Y/20» по срокам и названиям, и отдельно число ложных сроков.
2. Если стало хуже — не отправляй изменения, разберись (VERBOSE=1 покажет сырой текст).
3. Если стало лучше и ложных сроков 0 — подними числа в `tests/baseline.json`, чтобы эталон не откатывался назад.
4. Новые фото от пользователя добавляй в `tests/photos/` (длинная сторона ≤1600 px, JPEG ~88%) и в `tests/truth.json` (`name` — точное название из каталога `PRODUCTS` в index.html, `expires` — последняя дата на этикетке в формате `YYYY-MM-DDTHH:MM`). Правильный ответ бери с самого фото глазами, не из вывода программы.
5. Фото, снятые в другой день, требуют своего `today` — если добавляешь такие, обсуди с пользователем (сейчас все сняты 02.11.2026).
